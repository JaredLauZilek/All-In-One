# CLAUDE.md — Training (tr)

Backend home of the **Training** mini-app (Hyrox + endurance racing). The frontend lives
in the unified app at `web/src/apps/training/` (Week / Races / Settings under
`/training`); this folder holds the edge functions and migration ledger. **Everything
this app owns is prefixed `tr_` / `TR_` / `tr-`** (siblings: `fin_` financial-tracker,
`evs_` evs-scanner — never touch theirs).

## What this is

Jared's training hub for Hyrox, half/full marathons and (later) half/full Ironman:

- **Races** are the goalposts; the earliest dated upcoming race is the active goal.
- **Weekly plans** are generated by a rule engine (periodized blocks, volume
  progression, race-type templates) with an optional Claude fine-tuning pass, then
  pushed to Google Calendar.
- **Actual workouts** flow in from **intervals.icu** (runs/rides/swims — Garmin
  auto-syncs to it; free API, Basic auth with literal username `API_KEY`; credentials in
  `tr_settings.intervals_athlete_id/_api_key`, added 2026-09-06 after Strava gated its
  API behind a paid Strava subscription — the Strava OAuth path remains in the code,
  dormant) and Hevy (lifts, full set/rep detail), auto-matched to planned sessions.
- **Activities tab** (`/training/activities`, added 2026-09-06): intervals.icu-style
  weekly grid — per activity: time/distance/avg HR/pace/estimated steps (run cadence
  ×2 — Garmin sends no per-workout step total) + HR-zone mini-bars from
  `data.icu_hr_zone_times` (tr-sync stores a compact copy of each intervals.icu
  activity: scalars + arrays ≤12 long, nulls dropped); per week: gym vs cardio
  totals with Δ% vs the previous week. Gym bucket = strength + 'other' (Garmin
  logs Jared's gym sessions as generic "Workout").
- **Daily wellness** (resting HR, HRV, sleep, weight) also comes from intervals.icu —
  Garmin pushes its wellness stream there, so recovery-aware planning works WITHOUT
  Apple Health after all (0003, `tr_wellness`, one row/day). tr-plan-week and the bot
  feed the last 14/7 days to Claude; the dashboard shows a Recovery card. Verified
  live 2026-09-06: 33 days of RHR, 19 with HRV, 18 with sleep.
- **A Telegram bot** is the mid-week interface: /today /week /sync commands plus
  Claude-powered chat that can skip/move/update/add sessions (and mirrors those
  changes into Google Calendar). The dashboard is the once-a-week review tool.

Deliberate scope cut (Jared's choice 2026-09-05): **no Apple Health / sleep / HRV
source** — Strava + Hevy APIs only. Recovery-aware recommendations key off completed
load, not biometrics. (Adding sleep later = the Health Auto Export iOS app posting to
a new `tr-health-webhook` fn.)

## Architecture

```
web /training ──┬─ tables (owner RLS): tr_races, tr_plan_weeks, tr_planned_sessions,
                │                      tr_workouts, tr_settings, tr_chat_log
                ├─ tr-connect     status / Strava OAuth code exchange / disconnect
                ├─ tr-sync        Strava + Hevy → tr_workouts → match → mark done
                └─ tr-plan-week   rules → (Claude) → sessions + Google Calendar
Telegram ───────── tr-telegram-webhook  (verify_jwt FALSE, secret-header guarded)
```

- **`tr_tokens`** (Strava OAuth tokens) has RLS ON with **no policies** — the browser
  can never read it; only edge functions (service role) touch it. Keep it that way.
- `tr-connect`, `tr-sync`, `tr-plan-week` are `verify_jwt: true`. tr-sync/tr-plan-week
  also accept the project **anon JWT** (valid JWT, no user) — they then fall back to
  the sole `tr_settings` row's owner. That's how the Telegram webhook triggers /sync.
- `tr-telegram-webhook` is `verify_jwt: false`; security = the
  `X-Telegram-Bot-Api-Secret-Token` header must equal `TELEGRAM_WEBHOOK_SECRET`, and a
  chat must be paired via `/link <pairing_code>` (code lives in `tr_settings`, shown in
  the app's Settings).
- Timezone: fixed **+8h (MYT)** everywhere — Malaysia has no DST; don't "fix" this
  with Intl timezone lookups.

## Plan engine (tr-plan-week)

- Block from weeks-to-race: hyrox/half `base >10w · build 10–5 · peak 4–2 · taper 1`;
  marathon/70.3/IM `base >14 · build 14–7 · peak 6–3 · taper 2`; race week when the
  date falls inside the week; every 4th consecutive loading week becomes a **deload**.
- Run volume: `base_km = max(15, avg actual last 4w, last planned)` ×
  `{base 1.05, build 1.08, peak 1.0, deload 0.6, taper 0.5, race 0.3}`.
- Race-type templates in `skeleton()` (hyrox: intervals / strength ×2 / compromised
  session / long run; marathon: intervals / tempo / long; tri: swim/bike/run/brick).
  Long session lands on `tr_settings.long_run_day`.
- Claude pass (`ANTHROPIC_API_KEY`, model `ANTHROPIC_MODEL` ?? claude-sonnet-5) may
  reshape within guardrails (same week, 3–9 sessions, valid sports) — invalid output
  falls back to the skeleton. `generated_by` records `rules` vs `rules+claude`.
- Regeneration replaces only **status='planned'** rows (done/skipped survive) and
  deletes their old calendar events first.

## Secrets (Supabase → Edge Functions → Secrets)

| Secret | Feature it unlocks |
|---|---|
| `STRAVA_CLIENT_ID` / `STRAVA_CLIENT_SECRET` | Strava OAuth (app at strava.com/settings/api; callback domain = the Vercel domain) |
| `TELEGRAM_BOT_TOKEN` / `TELEGRAM_WEBHOOK_SECRET` | the bot (register webhook with the secret_token, see below) |
| `ANTHROPIC_API_KEY` (opt. `ANTHROPIC_MODEL`) | conversational bot + plan fine-tuning |
| `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` / `GOOGLE_REFRESH_TOKEN` (opt. `GOOGLE_CALENDAR_ID`) | calendar push |

Hevy's API key is NOT a secret here — it's stored in `tr_settings.hevy_api_key`
(owner-RLS row, single-user app), entered in the app's Settings.

Register the Telegram webhook (once, after setting the two Telegram secrets):

```bash
curl "https://api.telegram.org/bot<TOKEN>/setWebhook" \
  -d "url=https://vjqbircarzxcxrdzlyxj.supabase.co/functions/v1/tr-telegram-webhook" \
  -d "secret_token=<TELEGRAM_WEBHOOK_SECRET value>"
```

Google refresh token (once): Cloud Console → enable Calendar API → OAuth client
(Web, redirect `https://developers.google.com/oauthplayground`) → in OAuth Playground
(gear icon → use your own credentials) authorize
`https://www.googleapis.com/auth/calendar.events` → exchange code → copy refresh token.

## Deploying

- Edge functions: Supabase MCP `deploy_edge_function` (tr-connect / tr-sync /
  tr-plan-week `verify_jwt: true`; **tr-telegram-webhook `verify_jwt: false`**);
  `supabase/functions/` here is the source mirror.
- Schema: MCP `apply_migration`; mirror into `supabase/migrations/` (0001 applied live
  2026-09-05). Next migration: `0002_`.
- Frontend: push to main (single Vercel deploy — see `web/CLAUDE.md`).

## Gotchas

- Every integration must **degrade gracefully** — the app is fully usable with zero
  secrets set (rules-only plans, manual done/skip, no calendar). Keep it that way.
- The webhook always returns HTTP 200 (even on errors) — Telegram retries non-200s
  and you get duplicate message processing.
- tr-sync matching is same-MYT-day + compatible sport (a run can tick a `hyrox`
  session, a Hevy lift ticks `strength`/`hyrox`); first match wins.
- Claude action `id`s come from the context we send; the webhook only applies actions
  whose row actually belongs to the user (`eq user_id`), so a hallucinated id no-ops.
- Strava tokens rotate on every refresh — always persist the returned refresh_token.
